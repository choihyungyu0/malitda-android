# 말잇다 · Android 개발 구현 계약

이 문서는 Figma의 원안 위치 프레임, control-contract.json, UI 자산과 함께 사용한다. 현재 산출물은 디자인·프로토타입이며 APK 구현 완료를 뜻하지 않는다.

## 좌표와 레이어
- 원안 이미지: 853×1844 px. Figma 기준: 폭 390, 높이 1844×390÷853 = 843.09496.
- visualRect = sourceRect × 390÷853. 모든 수치는 x, y, width, height 순서.
- 원안 이미지는 배경 참고 레이어다. 실제 앱의 버튼·글씨·입력은 이미지 위의 네이티브 UI로 구현한다.
- 시각 프레임과 터치 권장 범위를 분리한다. 원안 위치를 검증할 때는 visualRect를 쓴다.
- 원안의 작은 최근 문장 행·체크박스·아이콘은 구현 시 최소 48dp 터치 영역을 확보해야 한다. 인접 영역 확장 충돌은 review/touch-recommendation-conflicts.json에 기록한다. 서로 겹치는 터치 영역을 그대로 구현하지 않는다.
- 390dp 초과 화면에서는 좌우 여백을 확장하고 콘텐츠 폭은 480dp까지 제한하는 구현 기준을 제안한다. 320dp·글자 확대에서는 고정 높이 대신 내용에 따라 세로 스크롤한다. 정확한 실기기 검증은 APK 이후 수행한다.
- 키보드 표시 시 창 크기 조정(adjustResize)에 대응하고 포커스 입력칸·오류 설명·저장 버튼을 스크롤로 노출한다. 시스템 상태표시줄·하단 내비게이션 안전 여백을 별도 반영한다.

## 입력 필드
|필드|타입|제한|빈 값|저장 시점|
|---|---|---|---|---|
|템플릿·핵심표현 검색|한 줄 검색|40자|전체 목록 복원|일시 상태|
|표현 제목|한 줄 텍스트|40자|허용, 내용으로 목록 제목 대체|저장 클릭|
|표현 내용|여러 줄 텍스트|80자|저장 차단|저장 클릭|
|보낼 문장|여러 줄 텍스트|200자|승인 차단|작성 세션만|
|카테고리|단일 선택|이름·장소·시간·메시지·자주 쓰는 말|기존 선택 유지|표현 저장|

글자 수는 사용자에게 보이는 글자 단위로 계산한다. Android 구현에서 한글 조합 중 문자를 자르지 않는다. 입력 완료 후 앞뒤 공백을 정리하고 중간 공백·문장부호는 임의로 바꾸지 않는다. 제목·검색은 줄바꿈을 공백으로 바꾼다. 길이 제한은 원안의 80자·200자 표기를 따르며 검색·제목 40자는 개발 기준 제안이다.

취소는 마지막 저장본을 유지하고, 초안은 확인 후 폐기한다. 수정과 동시에 저장하지 않는다. 입력 지우기는 해당 초안만 비우며 등록 데이터 삭제와 구분한다. 삭제 아이콘과 입력 프레임이 겹치면 지우기 버튼의 터치가 우선한다.

## 승인 상태
상태: Idle → Recording → Recognized → Editing → AwaitingApproval → Approved.
- 원문(rawTranscript)은 선택·수정·교정 뒤에도 그대로 보존한다.
- 표시·수정 문장(draftText)과 승인 문장(approvedText)을 분리한다.
- 후보 변경·직접 수정·재발화·초안 초기화 시 approvedText와 approvedRevision을 지운다.
- 공유·복사는 approvedRevision == draftRevision이고 approvedText == draftText일 때만 가능하다.
- 공유 직전에 같은 조건을 다시 검사한다. 비활성 버튼 모양만으로 보호하지 않는다.
- 자동 승인·자동 공유를 하지 않는다. 빠른 확인 모드는 확인 매체를 줄여도 승인 단계를 유지한다.
- 공유 취소·외부 앱 복귀 시 초안을 유지하고 공유 이력·상대방 정보는 저장하지 않는다.

## 표현·교정 데이터
- Expression: id, category, title?, text, favorite, createdAt, updatedAt. 최대 50개.
- Correction: id, rawExactText, approvedText, userScope, createdAt. 승인한 동일 오인식에만 적용하며 유사성만으로 새 후보를 만들지 않는다.
- 교정 개별 삭제, 교정 전체 초기화, 표현 개별 삭제, 모든 앱 데이터 초기화를 서로 다른 확인창으로 처리한다.
- 교정 초기화 후 기본 STT 결과로 복원한다. 등록 표현은 별도 삭제하지 않는 한 유지한다.
- 원음성 파일·공유 상대방·공유 이력은 별도 저장하지 않는다. 로컬 사용자 구분과 앱 백업 범위는 구현 시 명시한다.

## 오류·권한
- 마이크 거절: 시스템 권한 요청 반복 금지. 설정 안내, 등록문장, 직접입력 제공.
- 로컬 STT 오류·미설치·무응답: 초안 유지, 수동 재시도·등록문장·직접입력·AAC 안내. 외부 STT 자동 전환 금지.
- TTS 오류: 글·그림 확인 경로 유지. 듣기 버튼을 누르는 것 자체가 오류로 간주되어서는 안 된다.
- 저장 실패: 저장 전 초안 유지, 실패 이유·재시도 제공. 성공 메시지·목록 수 증가 금지.
- 잘못된 상세 ID: 목록으로 복귀하고 삭제된 항목임을 알린다.
- 공유 가능한 앱 없음·공유 취소: 승인된 현재 문장을 유지하고 복사 또는 수정 경로 제공.
- 네트워크 없음: 핵심 등록·선택·확인·승인 흐름을 유지한다.

## 화면 밖 운영 결정
- STT 엔진 채택·M0 학습 완료·온디바이스 성능은 이 디자인에서 확정하지 않는다.
- TTS 엔진의 오프라인 동작과 음성 설치 여부는 실기기로 검증한다.
- 문의 주소·최종 개인정보 처리방침·리워드 지급 기준은 출시 전 운영자가 확정한다.
- 원안 글꼴은 확인할 수 없어, 사용자 승인으로 Noto Sans KR을 가장 가까운 개발용 대체 글꼴로 쓴다.

## 개발 완료 조건
1. 핵심 등록→말하기→선택→수정→승인→공유가 실기기에서 동작한다.
2. 수정 후 이전 문장 공유, 승인 전 공유·복사, 취소 후 초안 손실이 없다.
3. 표현 0·1·50개, 빈 값·최대 길이·한글 조합·검색 결과 없음·저장 실패를 시험한다.
4. 마이크 권한 거절·STT 무응답·TTS 오류·공유 취소에서 복구 가능하다.
5. 320·390·430dp, 시스템 글자 200%, TalkBack·Switch Access, 최소 터치 영역을 확인한다.
6. 앱 송수신·모델 실행·음성 저장 여부를 측정한다. 디자인 프로토타입을 기술 검증 증거로 사용하지 않는다.
